# 引継ぎパッケージ チェックリスト（正式利用が決まった場合）

> 正式利用が決まった場合に、**ソースコード・設定資料・設計資料・運用手順書を一式で提供**するための
> チェックリストです。**秘密情報（パスワード・APIキー・Cookie・接続情報など）はパッケージ（ZIP）に含めません。**
> 秘密情報は正式な担当者の環境へ個別に設定します。

## 0. 前提・方針
- [ ] 提供形態（リポジトリ移管／複製／ZIP）のいずれが適切かを協議のうえ決定する
- [ ] ZIP提供の場合、**秘密情報を含めない**ことを受け渡し前に再確認する
- [ ] 引継ぎ後の運用・保守体制（担当者・連絡先）を取り決める
- [ ] 責任分担を分野ごとに文書化する（[SHIBUYA_PILOT_PLAN.md](SHIBUYA_PILOT_PLAN.md) の役割分担を基に）

## 1. ソースコード
- [ ] アプリ本体（フロントエンド・サーバー機能 `api/`・共通 `shared/`）
- [ ] スクレイパー（`scraper/`）一式
- [ ] スクリプト（`scripts/`：HTML生成・データ品質チェック等）
- [ ] CI 設定（`.github/workflows/`）
- [ ] ビルド設定（`package.json` / `vite.config.js` / `vercel.json`）
- [ ] `.gitignore` 等（秘密ファイルが除外されていることの確認）

## 2. 文書
- [ ] README（プロジェクト概要）
- [ ] DEPLOY.md（デプロイ・環境変数一覧・シークレットローテーション）
- [ ] OPERATIONS.md（日常運用・障害対応・バックアップ）
- [ ] SECURITY.md（セキュリティ方針・認証認可・既知の制約）
- [ ] CLAUDE.md（詳細仕様：イベントカード正準・天気・セキュリティ）
- [ ] DATA_SOURCES.md / THIRD_PARTY_NOTICES.md（出典・ライセンス）
- [ ] 持込み・試験運用資料（SHIBUYA_BRIEFING_READINESS / EVALUATION_SHEET / PILOT_PLAN）
- [ ] 本チェックリスト

## 3. データ
- [ ] データ形式の説明（`public/data/events.json` のスキーマ＝各項目の意味・書式）
- [ ] 手動イベント・上書き修正・操作履歴の保存場所と構造の説明
- [ ] サンプルデータ（**個人情報・秘密情報を含まないもの**）
- [ ] バックアップ・復元の対象と手順（Git履歴・管理データのエクスポート）

## 4. 外部サービス
- [ ] 利用中の外部サービス一覧（ホスティング／データ保存／通知／天気／座標／OCR）
- [ ] 各サービスの役割・前提プラン・無料枠と上限の説明
- [ ] 正式運用時に想定される費用と確認事項（[SHIBUYA_BRIEFING_READINESS.md](SHIBUYA_BRIEFING_READINESS.md) 費用節と整合）
- [ ] アカウント移管／新規取得のどちらにするかの取り決め

## 5. 環境変数
- [ ] **変数名と用途・既定動作の一覧**（値は記載しない）
- [ ] 必須／任意の区分、推奨設定（移行フラグの正式運用値を含む）
- [ ] 設定先（ホスティング環境・CIシークレット）の説明
- [ ] **実際の値は引継ぎ先で個別設定**（ZIPに含めない）

## 6. 管理アカウント
> 作成・変更の具体手順は **[ADMIN_ACCOUNT_SETUP.md](ADMIN_ACCOUNT_SETUP.md)**（ユーザー名・パスワードの作り方／変更／停止）を参照。
- [ ] アカウント定義の形式と項目（役割・所属・事務所・表示用ID 等）の説明
- [ ] **パスワードの安全な作成・登録手順**（ハッシュ化の方法）
- [ ] 権限（役割）の種類と、できること・できないことの一覧
- [ ] アカウントの停止・権限変更・パスワード変更時の手順（既存ログインの失効を含む）
- [ ] **実アカウント・パスワードはZIPに含めず、引継ぎ先で作成**

## 7. セキュリティ
- [ ] セキュリティ方針（SECURITY.md）の共有と説明
- [ ] 認証・認可・操作履歴・キャッシュ・CSRF 等の仕組みの説明
- [ ] 既知の制約・正式運用前に必要な設定（移行フラグの切替順序など）
- [ ] 脆弱性報告・問い合わせ窓口の取り決め
- [ ] シークレットのローテーション手順

## 8. バックアップ
- [ ] バックアップ対象の一覧（コード・公開データ・管理データ・操作履歴）
- [ ] バックアップ方法と頻度の説明
- [ ] 復元手順（事故時の戻し方）
- [ ] 引継ぎ時点のバックアップ取得（**秘密情報を除く**）

## 9. ライセンス
- [ ] 自作コードのライセンス（LICENSE）
- [ ] 第三者ライブラリのライセンス一覧（THIRD_PARTY_NOTICES.md）
- [ ] データの出典と取り扱い（DATA_SOURCES.md：公開情報・座標・気象・OCR抽出文 等）
- [ ] 公式情報・非公式の位置づけの明記

## 10. 操作研修（引継ぎ説明）
- [ ] 管理画面の操作（ログイン／下書き／確認／公開／修正／削除）の説明
- [ ] 権限・操作履歴・障害時連絡の説明
- [ ] デプロイ・更新の流れの説明（担当範囲に応じて）
- [ ] よくある操作・トラブルのFAQ

## 11. 引継ぎ確認
- [ ] 引継ぎ先の環境で**起動・表示・ログイン**ができることの確認
- [ ] テスト用イベントで**下書き→確認→公開→修正→削除**が一通り動くことの確認
- [ ] バックアップ・復元が実施できることの確認
- [ ] 連絡体制・責任分担・費用条件の合意（文書化）
- [ ] 引継ぎ完了の相互確認（チェックリストの消し込み）

## 12. 秘密情報をZIPに含めないこと（最重要）
- [ ] パスワード（平文・ハッシュとも）
- [ ] APIキー・トークン
- [ ] Cookie・セッション情報
- [ ] データベース／キャッシュの接続情報（URL・トークン）
- [ ] 通知用のシークレット・トピック名
- [ ] 管理アカウント定義の実値（`ADMIN_ACCOUNTS_B64` の中身など）
- [ ] その他、環境変数の実際の値
- [ ] `.env` 等の秘密ファイル

> 上記はパッケージに含めず、**引継ぎ先の正式担当者が自身の環境に個別設定**する。
> 万一含まれていないか、受け渡し前に必ず点検する。
