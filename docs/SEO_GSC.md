# SEO・Google Search Console 運用手順

（2026-07-02 作成。すべて無料で実施できる対策のみ）

## サイトのSEO構成（現状）

| 要素 | 状態 |
|---|---|
| sitemap.xml | スクレイプ毎に自動更新（53 URL・lastmod付き・イベント有無で priority/changefreq を出し分け） |
| robots.txt | Sitemap 宣言・主要クローラー/AIボット許可済み |
| canonical / OGP / Twitter Card | 全静的ページに設定済み |
| JSON-LD | トップ=WebSite/WebApplication、events.html=Event一覧、県ページ=BreadcrumbList+FAQPage+Event、guide=FAQPage+BreadcrumbList |
| 県ページの固有コンテンツ | イベント一覧＋**県内の募集案内所・地域事務所一覧（住所・電話・公式リンク）** |
| IndexNow | デプロイ毎に自動送信（Bing/Yandex 等。Google は非対応のため sitemap 巡回） |

## 「インデックス未登録」の原因と対策（2026-07-02 実施）

**原因**: 県ページ50件のうち、イベント0件の県（11県）と1〜2件の県（13県）は
県名以外がテンプレートと同一の「薄いページ」だったため、Google が
「クロール済み - インデックス未登録」として登録を保留していた（約29件と一致）。

**実施した対策**:
1. 全県ページに**県内の募集案内所・地域事務所一覧**（offices.json の実データ：名称・住所・電話・公式リンク）を掲載
   → 0件県も固有のローカル情報を持つ実用ページになった
2. meta description に事務所数を含めて県ごとに固有化
3. sitemap の priority/changefreq をイベント有無で出し分け（クロール資源を有効ページへ誘導）

## Google Search Console でやること（手動・無料）

デプロイ後、以下を実施する:

### 1. sitemap の再送信
GSC → 左メニュー「サイトマップ」→ `sitemap.xml` の行を確認 → 必要なら再送信。
（自動で再取得されるが、送信すると再クロールが早まる）

### 2. 未登録URLの確認
GSC → 「インデックス作成」→「ページ」→「クロール済み - インデックス未登録」を開き、
対象URLの一覧を確認する。大半が `/events/<県>.html` のはず。

### 3. 主要ページの再クロール依頼（1日あたり10件程度まで）
未登録だった県ページを、上部の「URL検査」に貼り付け →
「インデックス登録をリクエスト」。0件だった11県
（aomori, chiba, toyama, mie, shiga, wakayama, yamaguchi, oita, miyazaki, kagoshima, okinawa）
を優先して数日に分けて実施する。

### 4. 経過観察（2〜4週間）
- 「ページ」レポートで未登録数が減っているか週1で確認
- 反映には数日〜数週間かかる。**改善直後に未登録が残っていても正常**
- 「検出 - インデックス未登録」はクロール待ちなので操作不要

## 今後、無料でできる追加施策（未実施・任意）

- 独自ドメイン取得は有料のため対象外（現状 vercel.app のまま）
- X/SNSでのイベント紹介投稿（被リンク・言及の獲得）
- イベント詳細の個別ページ化（`/events/<pref>/<id>.html`）— ロングテール強化。
  ページ数が増えるため、まず現行50ページの登録が安定してから検討
- 「今週の自衛隊イベント」等の定期更新見出しを events.html に追加（更新性シグナル）

## 注意（やらないこと）

- 検索順位のための隠しテキスト・キーワード詰め込み（ペナルティ対象）
- 未登録を隠すための安易な noindex（インデックス機会を失う。内容の充実で解決する）
- 有料被リンクの購入
